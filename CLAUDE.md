# Heimvis: guide for Claude Code

(The repository and the Supabase projects are still named "heima"; the product is **Heimvis**.)

Norwegian app for shared flats (bokollektiv). Expo (React Native, TypeScript strict) + Supabase (EU). Goal: App Store as soon as possible. The owner works in cybersecurity: **security and architecture are judged at professional level.**

Read [docs/ROADMAP.md](docs/ROADMAP.md) for what is next and [docs/threat-model.md](docs/threat-model.md) before touching auth, RLS, storage or Edge Functions.

## Non-negotiable rules

### Database (the trust boundary)
Every new table:
1. `household_id` on every row; child tables use a composite FK `(parent_id, household_id) → parent(id, household_id)`.
2. `enable` **and** `force row level security`; policies use `(select private.is_member(household_id))` / `is_admin`.
3. Ownership columns (`author_id`, `created_by`, `user_id`) `default auth.uid()` and are **not** in the INSERT grant; WITH CHECK repeats `= auth.uid()`.
4. Column-level `grant insert (...)` / `grant update (...)`. Never grant identity columns, `role`, `status`, timestamps.
5. Length/enum CHECK constraints on all text.
6. Add the realtime trigger (`private.notify_household`); payloads stay notification-only.
7. Multi-row or rule-bearing writes are RPCs: `security definer`, `set search_path = ''`, explicit `private.require_uid()` / membership check, `revoke ... from public, anon`, `grant ... to authenticated`.
8. A new pgTAP file in `supabase/tests/database/` covering cross-household isolation, spoofing and immutable columns. `001_schema_security.test.sql` enforces schema-wide invariants. Never weaken it.
9. Schema changes only as new files in `supabase/migrations/`. Never edit a migration that has been deployed.

### App
- All user-facing text goes through `t` from `@/i18n`. Add the key to **both** `src/i18n/nb.ts` and `src/i18n/en.ts` (the `Strings` type enforces it).
- Screens call feature hooks in `src/features/*`, never `supabase` directly. Validate input with `schemas` from `src/lib/validation.ts` (mirrors DB constraints).
- Show errors through `userMessage()`; never render raw DB errors.
- UI comes from `src/components/ui.tsx`. Wrap a screen in `<Screen feature="...">`; buttons, chips and switches pick up the tab colour (`src/constants/theme.ts`).
- Accessible names: `aria-label` / `role` (react-native-web 0.21 ignores `accessibilityLabel`).
- Only the publishable key may ever be in the app (`EXPO_PUBLIC_*` is inlined). `src/lib/env.ts` refuses secret keys.
- Use `npx expo install` for dependencies (`EXPO_OFFLINE=1` in the cloud sandbox).

## Commands

```bash
npx tsc --noEmit && npx expo lint && npx jest --ci      # app checks
npx supabase@3.4.0 start -x studio,imgproxy,vector,logflare,supavisor,edge-runtime,mailpit,postgres-meta
npx supabase@3.4.0 db reset                             # apply migrations locally
npx supabase@3.4.0 test db                              # pgTAP (must stay green)
npx supabase@3.4.0 db lint --level warning --fail-on warning
npx supabase@3.4.0 db advisors --level warn --fail-on warn
npm audit --omit=dev --audit-level=high
```

E2E (two users, web build, `e2e/smoke.mjs`): needs the local stack, an SMTP sink on the
`supabase_inbucket_heima` container name (the mailpit image cannot be pulled in the
sandbox), and `npx expo start --web`. Then:
`MAIL_LOG=<sink log> NODE_PATH=$(npm root -g) node e2e/smoke.mjs`.
Every screenshot is checked for horizontal overflow at 390 px.

## Gotchas (learned the hard way)
- **Supabase CLI v3**: `db push` needs `--remote`; `functions deploy` has no `--project-ref` (it uses the linked project, `--use-api` avoids Docker). Keep the CLI pinned.
- PostgreSQL grants EXECUTE to PUBLIC on new functions; the foundation migration revokes this globally. pgTAP temp helpers therefore need an explicit `grant execute`.
- In plpgsql, `CASE` over record fields fails if a field is missing. Use `to_jsonb(rec) ->> 'col'`.
- Metro's file watcher does not work in the cloud sandbox: restart with `--clear` after edits.
- Typed routes (`.expo/types`) are regenerated by `expo start`; a new route can fail `tsc` until then.
- Visited tabs stay mounted on web: in E2E, wait for the URL (`page.waitForURL`), not for text.
- Expo's `--tunnel` needs an Expo login (`EXPO_TOKEN`).

## Workflow
- Branch per task, PR to `main`; CI must be green (App, Database, Secret scan, CodeQL `analyze`). `main` is protected.
- The DB reaches staging/prod only via the **Deploy database** workflow (prod needs approval).
- Commit messages and PR bodies in English; app text in Norwegian and English.
